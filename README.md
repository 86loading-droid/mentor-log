# 동행 기록 — 특수교육학부 멘토-멘티 학습 점검 웹앱

2~5개 팀이 멘토와 멘티 1:1로 공부하면서 회기마다 활동 인증 사진과 학습 결과물 사진(둘 다 필수)과 학습 내용을 기록합니다. 공통 루브릭(개념 알기·수업에 써 보기·돌아보고 연결하기 × 1단계 알아보기·2단계 설명하기·3단계 근거로 적용하기·4단계 새 상황에 쓰기)과 목표 달성 척도(GAS)로 성장을 점검하고, 교수자는 기록마다 피드백을 남깁니다. 운영은 학기 종료(2026-12-31)와 함께 끝납니다.

## 구성
| 파일 | 역할 |
|---|---|
| `index.html` | 앱 전체 (팀 화면, 교수자 대시보드, 시연 모드 포함) |
| `supabase.sql` | DB 테이블, 보안(RLS), PIN 확인 함수, 사진 저장소 |
| `config.js` | Supabase 연결값 (없으면 시연 모드) |
| `guide-science.pdf` 등 3종 | 팀별 안내문 (A4 한 장, QR 포함) |

## 처음 설정 (1회)
1. supabase.com 에서 새 프로젝트를 만듭니다 (Region: Northeast Asia (Seoul)).
2. SQL Editor 에 `supabase.sql` 전체를 붙여넣고 Run 합니다.
3. 저장소에 `config.js` 를 만들고 `window.MM_CONFIG = { url: "https://<프로젝트>.supabase.co", key: "<anon public key>" };` 를 넣습니다 (Project Settings > API Keys > Legacy 의 anon public). 이 키는 브라우저 공개용이며, 데이터 보호는 RLS와 PIN 함수가 담당합니다.
4. GitHub 저장소에 올리고 Settings > Pages 에서 `main` / `(root)` 로 배포합니다.
5. 앱에서 교수자 입장 → 교수자 PIN(6자리 이상)을 처음 한 번 정합니다. 배포 직후 바로 설정하십시오.
6. 팀 관리에서 팀을 만들고, 화면에 뜨는 팀 코드와 PIN 을 학생에게 전달합니다.

config.js 가 없으면 시연 모드로 동작합니다 (교수자 PIN 000000, 팀 코드 TDEMOA / PIN 1111).

## 보안 설계
- 모든 테이블은 RLS 로 직접 접근이 막혀 있고, PIN 을 확인하는 함수로만 읽고 씁니다. PIN 은 bcrypt 해시로 저장됩니다.
- 같은 대상에 PIN 을 5회 틀리면 10분 잠깁니다.
- 기록마다 사진 두 종류가 필수입니다: 활동 인증 사진(멘토·멘티 얼굴이 함께 보이게, 최대 2장), 학습 결과물 사진(최대 3장). 저장 전 촬영·보관 동의 체크가 필요합니다.
- 사진은 추측할 수 없는 긴 주소(UUID)로 저장되지만 공개 버킷이므로, 주소를 아는 사람은 볼 수 있습니다. 앱 밖으로 사진 주소를 공유하지 않도록 안내하고, 학기 종료 후 반드시 버킷을 비우십시오.
- 학기 초에 참여 학생에게 초상 촬영·보관(학기말까지) 동의서를 받아 두는 것을 권합니다.

## 학기 종료 절차
1. 교수자 > 내보내기: 활동기록 CSV, 피드백 CSV, 팀별 요약 CSV, 전체 JSON, 사진 ZIP 을 내려받습니다.
2. 학기 종료 칸에 `학기종료` 입력 후 삭제합니다.
3. Supabase > Storage > mm-photos > Empty bucket 으로 사진을 비웁니다.
4. 필요 없으면 Supabase 프로젝트를 삭제합니다 (무료 프로젝트 2개 한도 반환).

## 무료 요금제 주의
- config.js 는 따옴표가 빠지는 등 입력 실수가 있어도 url·key 를 읽어 냅니다.
- 약 1주일 동안 요청이 없으면 프로젝트가 일시정지됩니다. 학기 중에는 거의 문제가 없고, 정지되면 대시보드에서 Restore 를 누릅니다.
- DB 500MB, 파일 1GB. 사진은 1280px JPEG 로 자동 압축됩니다.
